# 分类与评分

## 主类别

| 类别 | 场景 |
|---|---|
| 登录与认证 | 登录、密码重置、验证码、SSO、普通权限申请 |
| 支付与账单 | 扣款异常、退款、发票、账单疑问 |
| 功能缺陷 | 功能报错、按钮失效等，不符合更具体类别的异常 |
| 性能问题 | 卡顿、超时、页面或接口慢 |
| 数据问题 | 数据丢失、不一致、导入导出异常 |
| 咨询与使用 | 使用方法、功能支持情况、最佳实践 |
| 安全与合规 | 疑似越权、账号被盗、隐私泄露、安全事件、合规请求 |
| 其他 | 证据不足以分类，或无法归入以上类别 |

按主要诉求分类。疑似越权归安全与合规，普通权限配置归登录与认证；数据泄露归安全与合规，普通数据不一致归数据问题。合规咨询不等于正在发生安全事故。

## 影响 impact

| 分值 | 证据锚点 |
|---|---|
| 1 | 单个用户非核心功能问题或一般咨询 |
| 2 | 少量用户轻微受影响，核心业务可继续 |
| 3 | 部分用户或一个部门业务受阻，但有替代方案 |
| 4 | 部门或更大范围核心业务受阻，且明确没有替代方案 |
| 5 | 全面故障，或报告数据丢失、账号失陷、敏感数据泄露等严重后果 |

按最匹配的已知业务影响评分，不以人数作为唯一标准。客户报告的严重后果可作暂定高分依据，但必须注明尚待核实。不能仅凭“安全”“退款”等类别词打 5 分。

## 紧急 urgency

| 分值 | 证据锚点 |
|---|---|
| 1 | 明确不紧急，可正常排期 |
| 2 | 希望尽快，但无明确期限或阻塞证据 |
| 3 | 明确近期期限，尚未明确临近或严重阻塞 |
| 4 | 当前严重阻塞，或明确临近业务截止时间 |
| 5 | 正在发生的生产事故、持续泄露或损失，需立即遏制 |

情绪只影响回复语气，不单独决定高分。“下午三点”等相对时间需结合工单时间和时区；无法确认则列入缺失信息，不擅自判断已超期。

## 缺失或冲突

- 某维度证据足够时正常评分，不受另一维度未知影响。
- 某维度缺少关键证据时暂用 3 分，表示待分诊的中间值，并非确认中等风险。信息冲突也暂用 3 分并列出冲突；有明确严重风险报告时，按风险证据暂定高分并交人工核实。
- 替代方案未知不能视为没有替代方案。例如一个部门无法登录，可暂定 impact=3，询问替代方案及业务影响。
- 摘要分别说明两个评分依据，缺失信息只列影响下一步的问题。低分不能取消疑似严重风险的人工核实。

## 等级

乘积 16–25 为 `high`，6–15 为 `medium`，1–5 为 `low`。分诊等级不代表合同 SLA、事故定级或处理时限。
